# TAS — идеальный забег: как устроен поиск и почему он наконец сходится

TAS-режим ищет ленту ввода (thrust/torque на каждом из 2700 тиков при 60 Гц),
при которой ракета спустится как можно глубже, не коснувшись стен пещеры.
Пещера детерминирована, ввод дискретен (6 комбинаций: `− ← → ▲ ▲+← ▲+→`),
поэтому пространство поиска конечно — перебор с лучом (beam search) и
отсечением ветвей, пересекающих стену.

Результат на 2026-11-09: **лента на 60.12 м (791 тик, ~13.2 с игрового
времени), проверена в реальной физике игры — PASS, max_err = 0.13 px**
(см. `ai/tas/tape.json`). Ракета спускается с равномерной скоростью ~230 px/с
без зависаний — предыдущая лента (60.12 м, 791 тик) стояла на месте
~25 секунд на глубине ~54 м.

## Что было сломано и как чинили

### 1. Стена — не гладкая кривая, а ломаная (16 px)

`cave.gd` строит стену ломаной по точкам каждые `STEP = 16` px (kill-Area2D и
коллизия используют один и тот же полигон). Модель поиска считала пересечение
с гладкой кривой `half(y)` — в местах излома настоящая стена оказывалась на
нескольких пикселях ближе, чем думала модель. Будущая лента «проходила» модель
и тут же умирала в игре (первый симптом: verify FAIL на тике 526).

Исправлено: в `tas_search.gd` и `tas_kernel.glsl` граница коридора считается
той же ломаной, что и полигон в игре (`edge_left/edge_right` через линейную
интерполяцию `left_x/right_x` на сетке 16 px). Погрешность модели против
реального полигона — ноль по построению.

### 2. Физика — не «чистый semi-implicit Euler», а движок с демпфированием

Свободное падение ракеты в игре систематически отличалось от модели: каждые
10 тиков `vy` росла всё медленнее. Трассировка движка (`_physics_process` с
нулевым вводом, замер `y/vy` каждый тик) показала:

- `physics/2d/default_linear_damp = 0.1` и `default_angular_damp = 1.0`
  (дефолты Godot 4, выставлять их никто не обязан — они просто есть):
  velocity гасится **до** применения сил, и именно это даёт лишние ~8 %
  расхождения по vy к тиру 60;
- силы (gravity + thrust) применяются после демпфирования и до позиции:
  `v *= (1 − 0.1·dt); v += (g + F/m)·dt; pos += v·dt` — бит-в-бит с движком;
- угловая скорость тоже гасится: `ω *= (1 − 1.0·dt)` каждый тик; `torque.gd`
  каждый тик выставляет `ω = ±4.0`, поэтому фактическое вращение =
  `4.0 × 59/60 = 3.9333` рад/с (именно это показывал API как `angle_vel`).

Модель проверена трассировкой движка (`_physics_process` без ввода и с
`api_thrust`): расхождение 0.0000 px по y и по vy на 60 тиках.

После калибровки лента проходит verify с `max_err ≈ 0.13–0.65 px` (сэмплы
каждые 4 тика) — ранее verify падал на тике 526.

### 3. Ширина луча — решающий фактор

| beam_main / beam_worker | лучший путь | результат verify |
|---|---|---|
| 24 / 32 | 24.04 м (все ветви мертвы к тику ~390) | n/a |
| 48 / 64 | 25.35 м | PASS, max_err 0.13 px |
| 96 / 128 | 60.12 м, 791 тик (≈25 с на «балансировке» на ~54 м) | PASS, max_err 0.65 px |
| 128 / 128 | 59.60 м (тот же медленный путь) | PASS |
| **192 / 192** | **60.12 м, 791 тик, ~230 px/с без остановок** | **PASS, max_err 0.13 px** |

Пещера глубоко за 25 м уходит в жёсткий зигзаг (центр до ±175 px за узел
256 px); узкий луч теряет все ветви у первого крутого излома, а 128-медленный
луч выживает там только зависанием (хвост ленты). Быстрый путь через излом
находится лишь при beam ≥ 192 (≈ 3.5 мин на RTX 4060 + CPU-поток). В меню и
`tas_headless.gd` по умолчанию теперь 192/192. Пул узлов в `tas_search.gd`
поднят до `MAX_NODES = 6 000 000` — иначе поиск австоп-ится по потолку памяти
задолго до конца при 192-wide луче.

## Как воспроизвести

```bash
# расчёт ленты (GPU-compute через Vulkan, иначе честный CPU ×2)
godot --path game -s tas_headless.gd -- --beam-main=192 --beam-worker=192 --out=user://tas.json
# headless (CPU ×2, без Vulkan)
godot --headless --path game -s tas_headless.gd -- --out=user://tas.json

# проверка ленты в реальной физике (вторая копия игры на другом порту)
godot --path game -- --api --port=8081 &
curl -X POST -d '{"lane":0}' http://127.0.0.1:8081/tas/verify
curl http://127.0.0.1:8081/tas/status   # PASS: tape replayed without touching walls
```

`game/tas_headless.gd` — тот же поиск из меню, но без GUI (для CI и машин без
дисплея); пишет ленту в `user://tas.json` или `--out=<path>`.

Лента в репозитории: `ai/tas/tape.json` (60.12 м, 791 тик, равномерный
спуск ~230 px/с; PASS в реальной физике, max_err = 0.13 px).

## Что осталось за рамками

- Verify всё ещё учитывает только выживание + инварианты (сравнение координат —
  только метрика `max_err`), сравнение траекторий бессмысленно — лента не
  записывается, а ищется.
- Проверка только на `time_scale = 1.0`.
- Теоретический предел глубины неизвестен: поиск упирается во время (кэп 2700
  тиков) и в ширину луча, не в физику.
- Зависимость счётной функции: снижение штрафа за скорость (`vy − 235`) ведёт
  к вымиранию луча на первом же крутом изломе (проверено: 2970 тиков, тупик
  ~30 м); усиление упреждающего веса `y+400` тоже вымирает (~24 м). Ровно
  235 px/с ceiling + слабое lookahead 240 px — локальный оптимум.
