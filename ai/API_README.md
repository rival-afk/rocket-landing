# Rocket Landing — HTTP API

Внешний API для управления игрой **Rocket Landing** и чтения её данных: счёт,
скорости, 5 лидаров, наклон ракеты, запуск параллельных игр (swarm), ускорение
симуляции. Версия API: **1.0.0** (совпадает с `config/version` в `project.godot`).

## Запуск

```powershell
# обычный запуск (окно)
& "путь\к\godot.exe" --path "путь\к\rocket-landing"

# другой порт API (по умолчанию 8080)
& "путь\к\godot.exe" --path "путь\к\rocket-landing" -- --port=8091

# headless (сервер без окна)
& "путь\к\godot.exe" --headless --path "путь\к\rocket-landing" -- --port=8091

# демо: окно сразу с N играми
& "путь\к\godot.exe" --path "путь\к\rocket-landing" -- --spawn=8

# если порт занят — выйти (для непоседливых запусков и тренажёров)
& "путь\к\godot.exe" --path "путь\к\rocket-landing" -- --quit-if-port-busy
```

Версия игры печатается при старте один раз:

```
Rocket Landing 1.0.0 (9a7e17e) built 2026-11-09
```

(`VERSION` берётся из `project.godot`, `COMMIT` = `git rev-parse --short HEAD`,
`BUILD_DATE` = дата сборки — проставляются скриптом `build.ps1`.)

API слушает на всех интерфейсах на выбранном порту (в выводе печатается
`Rocket Landing API: http://127.0.0.1:8080`). Если порт занят:

- игра **не падает**: API отключается, игра работает как обычно, в окне
  показывается плашка «API отключено: порт N занят»;
- с флагом `--quit-if-port-busy` игра завершится сразу (удобно для скриптов).

Для нескольких **отдельных процессов** запускайте с разными `--port`.
API-сервер — автолоад `RocketApiHost` (`api_host.gd`): живёт всё время работы
процесса и **переживает перезагрузку сцены** (`reload_current_scene`).

> ⚠️ API без авторизации и позволяет управлять игрой. Если не нужны внешние
> подключения из сети, запускайте игры на той же машине (или закройте порт
> файрволом).

## Протокол

- `GET`/`POST`/`DELETE`, тело — JSON (`Content-Type` не критичен), ответ — `application/json`;
- **каждое соединение закрывается после ответа** (`Connection: close`) — клиент
  не должен пуллироваться (см. замечание про PowerShell ниже);
- TCP_NODELAY включён на серверных сокетах — ответы не ждут NAGLE;
- позиции в px (`+y` вниз), скорости в px/s, **скор в метрах** (50 px = 1 м);
- значения в /state кэшируются **на физический тик**: повторные запросы в том же
  тике почти бесплатны (иначе 5 лидаров считались бы на каждый запрос).

### PowerShell и keep-alive (важно)

`Invoke-WebRequest` иногда переиспользует мёртвое соединение (сервер его закрыл
после ответа) и возвращает пустое тело без ошибки. Просто сделайте повторный
запрос — он уйдёт на новом соединении. Python `urllib` и `curl` пулы не держат
— с ними всё стабильно.

## Эндпоинты

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/` | имя, версия, список эндпоинтов |
| GET | `/health` | живость, версия, `time_scale`, число игр, рекорд |
| GET | `/state` | состояние **всех** игр |
| GET | `/state?lane=N` | состояние игры `N` |
| POST | `/control` | управление игрой `N`: тяга и руль; **ответ = состояние ПОСЛЕ применения** |
| POST | `/speed` | ускорение/замедление симуляции |
| POST | `/spawn` | запустить новую параллельную игру |
| POST | `/respawn` | пересоздать ракету в игре `N` |
| POST | `/reset` | без `lane` — перезагрузка сцены; с `lane` — пересоздание игры `N` |
| POST | `/lane/delete` | удалить игру `N` (алиас `DELETE /lane?lane=N`) |
| DELETE | `/lane?lane=N` | удалить игру `N` (нельзя удалить последнюю) |

### GET `/`

```json
{"name":"rocket-landing","version":"1.0.0","docs":"API_README.md","endpoints":[...]}
```

### GET `/health`

```json
{"ok": true, "version": "1.0.0", "time_scale": 1.0, "lanes": 8, "best": 143}
```

### GET `/state`

```json
{
  "best": 143,
  "time_scale": 1.0,
  "lanes": [
    {
      "lane": 0,
      "alive": true,
      "score": 87,
      "depth_m": 87.42,
      "vel_x": 12.3,
      "vel_y": 415.0,
      "speed": 415.2,
      "position": {"x": 3.1, "y": 4371.0},
      "angle": 22.5,
      "angle_vel": 0.8,
      "thrust": true,
      "torque": -0.25,
      "time_alive": 12.34,
      "lidars": {"right": 95.2, "right_down": 140.0, "down": 208.5, "left_down": 96.4, "left": 88.1}
    }
  ]
}
```

`GET /state?lane=N` — то же для одной игры (или `{"error":"lane not found"}` с HTTP 404).

#### Поля `lane`

| Поле | Смысл |
|------|-------|
| `lane` | номер игры (0 = главная, ids никогда не переиспользуются) |
| `alive` | жива ли ракета (`false` после касания стены) |
| `score` | счёт: **макс. глубина в метрах** (int, 50 px = 1 м); растёт **только при падении вниз** |
| `depth_m` | то же с точностью 0.01 м (float) |
| `vel_x`, `vel_y` | скорость по осям, px/s (`+y` = вниз) |
| `speed` | модуль скорости, px/s |
| `position` | `x`, `y` в пикселях (мировые координаты своей игры) |
| `angle` | наклон ракеты в **градусах**, 0 = вертикально, (-180, 180]; + = по часовой |
| `angle_vel` | угловая скорость, рад/с; + = по часовой |
| `thrust` | применённая тяга сейчас (по данным API или клавиатуры) |
| `torque` | применённый руль сейчас, [-1, 1] |
| `time_alive` | секунд с момента (пере)создания ракеты (по физике, зависит от `time_scale`) |
| `lidars` | расстояния до стен по 5 направлениям, px (макс. `280`) |

#### Лидары (5 лучей из носа ракеты)

| Ключ | Направление |
|------|-------------|
| `right` | вправо (→) |
| `right_down` | вправо-вниз (↘) |
| `down` | вниз (↓) |
| `left_down` | влево-вниз (↙) |
| `left` | влево (←) |

Значение = расстояние до стены в px; `280.0` = стены в радиусе нет.

### POST `/control`

```json
{"lane": 0, "thrust": true, "torque": -1}
```

- `lane` — номер игры (по умолчанию `0`),
- `thrust` — `true`/`false`: тяга двигателя (как клавиша ↑),
- `torque` — `-1` (влево), `0`, `+1` (вправо); клампится в [-1, 1],
- **ответ — снимок состояния ПОСЛЕ применения ввода** (тот же формат, что `/state?lane=N`).

То есть `/control` — это «сделай + сразу скажи, что получилось»: клиент не
обязан делать отдельный `/state`. Ответ неявный, но последовательный именно так.
Клавиатура (↑, ←, →) работает параллельно; если хотя бы одно из полей задано —
поле применяется, остальное не трогается.

### POST `/speed`

```json
{"scale": 4.0}
```

`Engine.time_scale = 4.0`. Клампится в [0.05, 20]. `{"scale": 1.0}` — нормальная скорость.

⚠️ При больших коэффициентах физика делает крупные шаги за тик. Предел
безопасности: перемещение за тик = `vel × time_scale / 60`; стены толщиной
1100 px, поэтому при скорости ≤ 1500 px/s и `time_scale` ≤ 10 всё безопасно.
У ракеты включён `continuous_cd = CAST_SHAPE` (CCD) — туннелирование через
стены невозможно даже при больших шагах. Для тренажёра смело `2.0–8.0`.

### POST `/spawn`

```json
{"lane": 4, "lanes": 5}
```

Запускает новую параллельную игру. Каждая игра — **независимая**: свой мир
(`SubViewport` + `World2D`), своя физика, своя **одинаковая** детерминированная
пещера. На экране окно делится сеткой (1×1 → 2×2 → 3×3 → 4×N) по числу игр.
`lane` у новых игр всегда новый (никогда не переиспользуется, даже после удаления).

Визуал в swarm-режиме: **только кадр пещеры + номер игры + статус
(`● ALIVE` / `✖ CRASHED`)** — никаких числовых метрик. В solo (одна игра)
дополнительно показываются счёт в метрах, `BEST`, наклон (`ANG`) и полоски
`VEL X/Y` и 5 лидаров. Игры со `✖ CRASHED` перестают рендериться
(`UPDATE_ONCE`) — сильно дешевле при большом числе замёрзших игр.

При смерти: solo → перезагрузка сцены, в параллельных играх → только эта игра
замирает (`freeze`), остальные продолжают; API при этом доступен всегда.

### POST `/respawn`

```json
{"lane": 2}               → {"ok": true, "lane": 2}
{"lane": 99}              → 404 {"error": "lane not found"}
{}                         → 400 {"error": "lane required"}
```

Пересоздаёт ракету в игре `N` (мир/панель остаются, id игры не меняется).

### POST `/reset`

```json
{"lane": 1}  → пересоздать игру 1 (как /respawn)
{}            → {"ok": true, "reloading": true}
```

Без `lane` — полная перезагрузка сцены (только `reload_current_scene`).

**Что происходит с API во время перезагрузки:** автолоад `RocketApiHost`
остаётся жив, сокет не закрывается. Пока сцена мертва (~50–200 мс), хост отвечает
`503 {"error":"scene reloading","retry_after_ms":500}` с заголовком `Retry-After: 1`.
Клиент НЕ получит connection-refused или повисший сокет. Рекомендация клиенту:
ретрай с backoff ±100–300 мс, после восстановления (первый `200 /health`) можно
продолжать.

### DELETE `/lane?lane=N`  /  POST `/lane/delete`

```json
{}→ {"ok": true, "lane": 2, "lanes": 3}          (удалено)
                              → 400 {"error":"cannot delete the last lane"}
                              → 404 {"error":"lane not found"}
```

Удаляет одну параллельную игру целиком (её `SubViewport` и мир). Остальные
игры не трогает. `lane`-ids убранной игры больше никогда не выдаются.

## Примеры

### curl

```bash
curl http://127.0.0.1:8080/health
curl "http://127.0.0.1:8080/state?lane=0"
curl -X POST -H 'Content-Type: application/json' -d '{"lane":0,"thrust":true}'  http://127.0.0.1:8080/control
curl -X POST -d '{"scale":4}'                        http://127.0.0.1:8080/speed
curl -X POST -d '{}'                                 http://127.0.0.1:8080/spawn
curl -X DELETE "http://127.0.0.1:8080/lane?lane=3"
```

### PowerShell

```powershell
(Invoke-WebRequest http://127.0.0.1:8080/health -UseBasicParsing).Content

$body = @{ lane = 0; thrust = $true } | ConvertTo-Json
Invoke-WebRequest http://127.0.0.1:8080/control -Method Post -Body $body -UseBasicParsing

Invoke-WebRequest "http://127.0.0.1:8080/lane?lane=3" -Method Delete -UseBasicParsing
```

## Коды ответов

| Код | Значение |
|-----|----------|
| 200 | OK |
| 400 | некорректное тело (невалидный JSON / нет обязательного поля / удаление последней игры) |
| 404 | игра не найдена / неизвестный путь |
| 405 | метод не поддерживается |
| 503 | идёт перезагрузка сцены — ретрайте через ~500 мс |

## Что видно на экране

- solo (1 игра): кадр + счёт (м), `BEST`, `ANG`, полоски `VEL X/Y`, 5 лидаров;
- swarm (≥2 игр): сетка `2×2` / `3×3` / `4×N`, в каждой ячейке только кадр +
  цветной номер `GAME N` и статус (`● ALIVE` / `✖ CRASHED`, рамка краснеет);
- `--spawn=N` — стартовать сразу с N играми (удобно для демо тренировки).

## Заметки

- Счёт/рекорд: растёт только при падении вниз; полёт вверх не считается.
- Рекорд общий на все игры, сохраняется в `user://rocket_landing_best.txt`
  (`%APPDATA%\Godot\app_userdata\Rocket Landing\`).
- Касание стены убивает; solo → перезагрузка сцены, swarm → только эта игра.
- Валидация JSON тела мягкая: пустой батч = `{}`, невалидный JSON = HTTP 400.
